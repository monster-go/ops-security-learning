# 01 — PSR-4 自动加载

> 对应 [PHP 概览](/php/) 第 1 节

---

## 1.1 为什么需要 PSR-4

在 PSR-4 出现之前，PHP 项目常用手动 `require`/`include` 逐个引入类文件，或使用各种自定义的 autoload 函数。这带来两个问题：

1. **维护成本高** — 每新增一个类就要改引入列表
2. **标准不统一** — 不同项目的目录结构与命名规则各异，协作困难

PSR-4（*Autoloading Standard*）由 [PHP-FIG](https://www.php-fig.org/) 制定，核心思想是：

> **命名空间前缀** 对应 **基础目录**，类名对应 **相对路径**，由 autoloader 按规则自动找到文件。

Composer 默认采用 PSR-4，Laravel、Symfony 等主流框架也遵循此规范。

---

## 1.2 规范要点

### 命名空间与类名

- 完全限定类名（Fully Qualified Class Name）形如：`\<NamespacePrefix>\<SubNamespace>\...\<ClassName>`
- 命名空间前缀与基础目录一一对应，可以有多个前缀映射到不同目录
- 类名中的 `\` 替换为目录分隔符 `/`，再加 `.php` 后缀即为文件路径

### 映射规则示例

| 命名空间前缀 | 基础目录 | 类全名 | 文件路径 |
|-------------|---------|--------|---------|
| `App\` | `src/` | `App\Controller\UserController` | `src/Controller/UserController.php` |
| `App\Model\` | `src/Model/` | `App\Model\User` | `src/Model/User.php` |
| `Vendor\Package\` | `lib/` | `Vendor\Package\Util\Helper` | `lib/Util/Helper.php` |

### 大小写

PSR-4 **推荐**（REC）文件名与类名大小写一致。在 Linux 等区分大小写的文件系统上，大小写不一致会导致「类找不到」的隐蔽错误。

## 1.3 Composer 中的 PSR-4 配置

`composer.json` 中最常见的 autoload 段：

```json
{
  "autoload": {
    "psr-4": {
      "App\\": "src/",
      "App\\Tests\\": "tests/"
    }
  }
}
```

说明：

- 键是命名空间前缀，**必须以 `\` 结尾**（写 `"App\\"` 是因为 JSON 转义）
- 值是对应的基础目录（相对项目根目录）
- 修改后需执行 `composer dump-autoload` 重新生成 `vendor/autoload.php` 及 classmap

### 最小可运行示例

**目录结构：**

```
my-app/
├── composer.json
├── src/
│   └── Hello.php
└── public/
    └── index.php
```

**`composer.json`：**

```json
{
  "name": "demo/my-app",
  "autoload": {
    "psr-4": {
      "Demo\\": "src/"
    }
  },
  "require": {}
}
```

**`src/Hello.php`：**

```php
<?php

namespace Demo;

class Hello
{
    public function greet(string $name): string
    {
        return "Hello, {$name}!";
    }
}
```

**`public/index.php`：**

```php
<?php

require __DIR__ . '/../vendor/autoload.php';

use Demo\Hello;

echo (new Hello())->greet('World');
```

**运行：**

```bash
composer install   # 或 composer dump-autoload
php public/index.php
# 输出: Hello, World!
```

## 1.4 手动注册 PSR-4 Autoloader（无 Composer 时）

理解底层机制有助于排障。PHP 内置 `spl_autoload_register` 可注册自定义加载逻辑：

```php
<?php

spl_autoload_register(function (string $class): void {
    $prefix = 'Demo\\';
    $baseDir = __DIR__ . '/src/';

    $len = strlen($prefix);
    if (strncmp($prefix, $class, $len) !== 0) {
        return; // 不是此前缀，交给其他 loader
    }

    $relativeClass = substr($class, $len);
    $file = $baseDir . str_replace('\\', '/', $relativeClass) . '.php';

    if (file_exists($file)) {
        require $file;
    }
});
```

Composer 生成的 autoload 本质上是更完善、支持多前缀与 classmap 优化的版本。

## 1.5 常见目录结构实践

### 典型 MVC 应用

```
app/
├── Controller/
│   └── UserController.php    # App\Controller\UserController
├── Model/
│   └── User.php              # App\Model\User
└── Service/
    └── UserService.php       # App\Service\UserService
```

对应 `composer.json`：

```json
"autoload": {
  "psr-4": {
    "App\\": "app/"
  }
}
```

### 多模块 / Monorepo

```json
"autoload": {
  "psr-4": {
    "App\\": "src/App/",
    "Shared\\": "src/Shared/",
    "Module\\Billing\\": "modules/Billing/src/"
  }
}
```

每个前缀独立映射，避免所有类堆在同一根目录。

## 1.6 排障清单

| 现象 | 常见原因 | 处理 |
|------|---------|------|
| `Class "App\Foo\Bar" not found` | 命名空间与文件路径不一致 | 核对类顶部的 `namespace` 与目录层级 |
| Linux 正常、部署后报错 | 文件名大小写与类名不一致 | 统一 PascalCase 文件名 |
| 改完类仍加载旧代码 | autoload 缓存未更新 | `composer dump-autoload -o` |
| 新增目录不生效 | 未在 `composer.json` 注册前缀 | 检查 `psr-4` 并 dump-autoload |
| 第三方包类找不到 | 未 `composer install` | 确认 `vendor/` 存在且已引入 `vendor/autoload.php` |

**调试技巧：**

```bash
# 查看 Composer 解析后的 PSR-4 映射
composer dump-autoload -v

# 确认 autoload 文件是否被引入
php -r "require 'vendor/autoload.php'; var_dump(class_exists('App\\YourClass'));"
```

## 1.7 PSR-4 与相关标准

| 标准 | 关系 |
|------|------|
| **PSR-0** | 早期 autoload 标准，已废弃，老项目可能仍见 |
| **PSR-4** | 当前主流，更简洁的目录映射 |
| **PSR-12** | 代码风格（缩进、命名等），与 autoload 互补 |
| **classmap** | Composer 另一种 autoload 方式，适合无命名空间的遗留代码 |

Composer 可同时配置 `psr-4` 与 `classmap`：

```json
"autoload": {
  "psr-4": { "App\\": "src/" },
  "classmap": ["legacy/"]
}
```

---

## 1.8 小结

1. **PSR-4 = 命名空间前缀 → 基础目录 + 类名 → 相对路径 `.php`**
2. **Composer** 是生产环境事实标准，改 `composer.json` 后记得 `composer dump-autoload`
3. **Linux 部署** 务必保证文件名大小写与类名一致
4. 排障时先核对 `namespace`、目录结构、autoload 配置三者是否一致
